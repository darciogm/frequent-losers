\section{Overview}

This package contains all code and data descriptions needed to
replicate the results in ``Screening for Bid Rigging with Frequent
Losers in Public Procurement.'' The analysis was conducted in R~4.5.2
on Ubuntu 22.04 (WSL2). Total runtime is approximately 25 minutes on
a 16-core machine.

\section{Replication Instructions}

\subsection{Step 0: Data build (if parquets are missing)}

The Python build script converts the raw Stata file into Parquet:

\begin{verbatim}
cd paper3-frequent-losers
python3 scripts/00_build_bidlevel.py
\end{verbatim}

\noindent This takes $\sim$6 minutes and produces five Parquet files in
\texttt{data/processed/}. Skip if the Parquet files are already present.

\subsection{Step 1: Run the R pipeline}

\begin{verbatim}
cd papers_finais/paper1_screening
Rscript code/00_master_v4.R
\end{verbatim}

\noindent The master script runs all 22 analysis scripts sequentially
(Phase~1: data infrastructure; Phase~2: core analyses; Phase~3:
robustness; Phase~4: outputs). Runtime is $\sim$25 minutes on 16
cores. Intermediate results are cached at \texttt{/tmp/p3v4\_*.rds};
delete these to force a clean run.

\subsection{Step 2: Additional figures}

\begin{verbatim}
Rscript code/figures_new.R
\end{verbatim}

\noindent Produces three additional figures (corner solution, dispersion
paradox, enforcement flowchart). Requires
\texttt{bid\_level\_analysis.parquet} from the upstream data build and
\texttt{cartel\_primitives.csv} from the companion structural paper.

\subsection{Step 3: Compile manuscript}

\begin{verbatim}
cd manuscript/v4
pdflatex paper_screening_v4.tex
bibtex paper_screening_v4
pdflatex paper_screening_v4.tex
pdflatex paper_screening_v4.tex
\end{verbatim}

\section{Notes}

\begin{itemize}
\item The IQR threshold uses \texttt{median + 1.5 $\times$ IQR} (not
  the Tukey rule \texttt{Q3 + 1.5 $\times$ IQR}). This is intentional;
  see Section~4.2 of the paper.
\item Standard errors are clustered at the item level throughout.
\item \texttt{fixest} uses \texttt{lean = TRUE} except in the
  Bajari--Ye first stage (script 06), which requires full model objects.
\item The pipeline uses up to 16 threads (\texttt{data.table} and
  \texttt{fixest}). Reduce \texttt{NCORES} in \texttt{00\_setup.R} if
  your machine has fewer cores.
\end{itemize}
